# Working-set support-table validation completion

> Historical record. This document preserves its original checkpoint and may describe retired providers, interfaces or plans. Use the [current documentation](../../README.md) for supported setup and behavior.

This completes the validation-responsibility wording in the unchanged
[R1 proposal](working-set-support-table-proposal-r1.md), source `29e957f`,
SHA-256 `ecf32b07ae9e83b4ae259d4e680273ca92ed05513e7c1ab40c184ab2941ebf5e`.
Bryan subsequently authorized the expanded Mesh implementation and a new Luna
goal loop to finish the producer feature. This completion does not select a
deployment, freeze identifiers or claim source/package/native acceptance.

R1's sentence that the packaged public profile schema must reject malformed
indices independently is replaced by the following exact division:

1. The packaged structural schema independently enforces closed object shapes,
typed support positions, existing nullability, static integer bounds 0..8,193,
table/array lengths and duplicate complete table maps where expressible.
2. The supported pure native validator additionally requires exact Python
integer type, excluding booleans and integral floats; a reference less than
the actual enclosing table length; complete canonical-map uniqueness and
strict byte ordering; no unused entries; exact scope/table pairing; and every
unchanged support, clock, coverage and record semantic check.
3. These native checks run on direct native inspection, bridge admission and
reconstructed public view admission. They are mandatory even if the structural
schema accepts the input. No generic callback or bypass is added.
4. Owner callbacks and vectors establish exact no-coercion and canonical-byte
restoration in addition to object equality. Python object equality alone does
not distinguish `1` from `1.0`. NativeState retains the exact paired table and
references; no silent normalization repairs malformed input.

Draft202012 permits integral floats for its JSON integer type. Static bounds
cannot prove a sibling table's actual length, canonical ordering or complete
use. The completion assigns those responsibilities explicitly; it weakens no
boundary admission or independent Mesh proof/receipt rule.

Public preparation supplies immutable mappings and tuples. Per-entry resolvers
must support those admitted containers, borrow the exact paired full maps only
for the current operation and emit existing detached rules. They must not
expand a whole metadata roster or retain scratch after preparation. Existing
detached read results keep their self-contained full-support values; actual
output copies remain caller-owned and included in applicable qualification.
No result-lease API, hidden historical registry or cross-process heap pool is
introduced by this representation change.

All other R1 rules remain: whole-eight-field identity; frame-local pairing;
8,194-entry structural ceiling; historical uncertainty semantics; immutable
window; independent active/recent branches; original limits and funded
table/key/container/scratch/copy/old-new lifetimes. Source-capacity and physical
memory savings require implementation and measured qualification. The earlier
wrapper arithmetic and refused partial 2,000-row scopes remain their original
bounded evidence.

The new exact native/request/profile schema tuple must be reviewed together
before its contract freeze. Retaining unreleased candidate literals permits no
hybrid map/table admission or automatic fallback under one accepted descriptor.
Legacy API4 rows, active/full schemas, normal service selections and the dark
delta disposition remain unchanged.
