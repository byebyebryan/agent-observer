## Database-only query check

The official catalog documentation describes default log scanning/metadata
repair and an explicit `useStateDbOnly=true` mode. A later independent read
probe sent that flag with the same explicit source kinds to both existing
owning daemons. Both queries returned complete catalogs: 89 Snap and 353 Starship
rows, with no missing session-tree-root IDs. This establishes accepted query
shape and available native metadata, not isolated passivity or Resume support.

The earlier ordinary comparison and installed a16 collector used the default
catalog mode. No filesystem mutation audit was performed, so this report does
not claim that default reads had no native housekeeping writes. The later counts
also come from a different time/mode and do not establish equivalent inventory.
Database-only placeholder/history coverage and no-repair semantics need the
isolated native gate specified in the reconciled plan.

No ordinary sessions were started, resumed, stopped, killed or renamed. No
TUI-closure case, Claude native case, provider configuration change, hook apply,
managed selection or frontend change was performed. The selected a16 remains
the same accepted operational baseline; D1-D4 in the reconciled plan remain open.
