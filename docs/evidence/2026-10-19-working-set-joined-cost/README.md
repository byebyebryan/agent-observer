# Joined canonical collection and Reader cost

The controlled 500-row comparison now joins actual canonical collection and
parent acceptance to ordinary public Mesh Reader delivery. The same accepted
state supplies both full and working-set profiles. Across two whole-trial
replicates per interpreter, the derived working-set total is 80.34–80.86% lower,
passing the 30% target for this fixture. All 96 fresh watch/proof/facade
acquisitions and retirements pass, with identical selected DTOs and complete
current coverage. This is synthetic-provider evidence, not native-provider cost
or whole-producer acceptance.

Each trial contains three controlled burst generations and four fresh reads of
each profile per generation. The profile order is swapped between replicates.
The table uses medians of the two complete trial totals, not pooled generation
samples. There is no warmup or failed-case retry. The immutable tuple is

`bfa91a6936a089d37c1a83752d3267148ba7dc69`.

The fixture contains 500 distinct thread/root identities: two loaded running
rows, two recent parked rows and 496 old parked rows. All turn replies contain
metadata only, with empty items. Actual canonical runtime/history workers run
through the captured default factory, original WNOWAIT/group-stop/wait order,
strict parent parser and `State.accept`. Source wall/BOOTTIME authority comes
from those accepted canonical samples; no synthetic accepted-clock argument is
injected. Full `viewRevision` and working-set `observationRevision` join the
same accepted revision, while working-set projection revisions retain their own
namespace. Both accepted component counters and the original history sample
remain unchanged through the paired reads.

Each full body is about 902 KB; the four selected bodies total 7,469 bytes,
about 0.83%, below the one-quarter prerequisite. Expected identities, all 6,000
thread/root joins, selected DTO equality and body fractions are checked after
the measured loop. The full consumer's selection work runs inside its read
window. Already detached rows are retained by reference for later comparison.

Let `P` be continuous parent process CPU through the three-generation loop,
including service-thread, acceptance, native IPC, Mesh, Reader, proof, facade,
filter, watch retirement and harness work. `F` and `W` are its disjoint full and
working-set read windows. `C` is direct `wait4` CPU for the six canonical
workers; `S` is the controlled provider server's full-lifetime direct `wait4`
CPU, counted once. Normal cyclic GC stays enabled, no explicit collection is
used, and the service heartbeat retains its 10-second default.

The observed paired run is `P + C + S`. The compared totals are derived as
`full = (P - F - W) + C + S + F` and
`working = (P - F - W) + C + S + W`. They share one actual producer and provider
fixture cost. They are not two independent observed pipeline runs, and no
cross-fixture component medians are added. No parent oracle CPU is subtracted;
setup/imports and final owner/process shutdown are outside the parent window,
while each watch's retirement is inside its read window. Server startup and
qualification CPU are conservatively included in `S`.

Primary independently checks all arithmetic, 244 captured loaded-module hash
references, the 2,223 Observer and 1,728 Mesh source files, all exact source
sample/DTO joins and process/endpoint/path cleanup. All 24 workers and four
servers are reaped; no Runtime thread, peer, Reader connection, Bridge handler
or owned socket remains. Every trial uses the shared exclusive qualification
lock. Exact reports, stdout/stderr, runner, fixture server, plan and primary
controllers are under `artifacts/`; hashes and original paths are in
`receipt.json` and `SHA256SUMS`.

Default canonical limits remain 1,000 catalog rows, 1,000 saved
