isolated native operator proofs and later ordinary runtime, installed artifact

### Direct-reader native cases

The next private namespace added a disposable machine ID so the native Linux
PID-domain formula could be checked exactly. The provisional file reader joined
the short job ID and full session UUID, verified process birth in that domain,
and sampled while a native attached model turn ran. It observed `busy` with
`tempo=active`, then `idle` with `state=done, tempo=idle`. The work-state change
clock stayed fixed while later presence reads advanced independently. The
exact-session transcript check confirmed one user and one assistant record and
the expected tiny assistant marker. See
[stage 2 observations](claude-stage2-observations.jsonl).

Completion normalization remained unknown because the first reader expected
numeric terminal timestamps. This live case exposed a parser gap; it is not an
accepted terminal normalization result. Retained job state remains distinct
from a current worker and an attached client.

A further disposable case enabled Bash with native `permissions.ask=["Bash"]`.
The TUI held a permission request, and the direct registry supplied 17 samples
of `status=waiting` with job `state=working, tempo=blocked`. The initial reader
left these unknown because it required active tempo; that guard also needs
correction. An explicit operator Escape produced an error tool-result whose
in-memory content matched a permission rejection, followed by idle/idle
metadata. No tool arguments or output were retained. This proves a held native
approval and rejection, not successful tool execution or generic cancellation.
See [stage 3 observations](claude-stage3-observations.jsonl). The corrected
reader must pass another native run before these mappings are accepted.

The corrected reader passed that follow-up. Stage 5 returned
`needs_input`/approval with current verified worker presence during the held
native permission dialog, then unknown work after rejection rather than
inventing completion. Stage 6 returned `working` while busy and `settled` after
the exact-session tiny completion. Native ISO terminal timestamps and later
registry idle writes are handled independently. The complete Claude collector
verified the installed artifact and returned current source coverage in roughly
126 ms. After the operator terminated the exact disposable worker, the job
remained retained/settled with its original terminal clock; worker and client
presence were unknown. See [stage 5](claude-stage5-observations.jsonl) and
[stage 6](claude-stage6-observations.jsonl). Earlier
[stage 4](claude-stage4-observations.jsonl) records the ordering guard failure
that prompted the final correction.

A separate [ordinary passive read](claude-ordinary-passive-read.json) found two
existing interactive sessions with exact process-birth/executable validation.
Their original idle/work timestamps were preserved. This invoked no provider
entry point and changed no compatibility setting. It establishes foreground
metadata visibility, not new foreground transition or Agent View rollout.

Stage 8 passed the separate lifetime gate. The native process topology contained
supervisor, PTY hosts and session workers before attachment. The attached TUI
client was a distinct child of disposable tmux. After native approval of a
harmless sleep tool, the operator closed only that attachment client. All five
preexisting provider process births survived; verified worker presence and
working state continued, then the job reached done/settled. The exact-session
assistant completion marker was checked in memory after viewer exit. See
[stage 8 observations](claude-stage8-observations.jsonl). Persisted roster static
review independently distinguishes PTY-host PID/birth from repl PID/birth;
client attachments exist only in memory and supply no passive binding route.

Stage 9 tested ordinary bare entry separately, with Agent View enabled and
`defaultToAgentsView=false`, `leftArrowOpensAgents=false`. This entry created
one interactive worker beneath tmux and no supervised job. After native
approval and while its sleep tool was alive, closing the disposable viewer
removed the provider worker; the session registry became empty. The source
reported no logical session-end claim. See
[stage 9 observations](claude-stage9-observations.jsonl).

**Enabling Agent View alone does not move bare-TUI work into the supervisor.**
The migration needs a proved native supervised creation route that preserves
individual TUI entry. Native short-ID attach is accepted for a current verified
background job. Bare foreground resume/new creation is not a substitute.
Automatic task submission from the original `--bg '<task>'` also remains
unexplained. Later stage 10 and ordinary trials resolve the empty supervised
creation route without relying on that original positional-task case.

All retained evidence is bounded metadata, counts, booleans and finite reason
codes. Native `providerEnv`, other raw fields, credentials, prompt/response/tool
content and terminal captures are excluded. The files deliberately retain
unrecognized early state as such; a later static vocabulary finding does not
retroactively turn those observations into measured state coverage.

## Codex 0.160.0

The [filtered native results](codex-native-results.json) verify the managed
release by SHA-256 plus executable/device/inode evidence and tie the existing
Unix listener to its exact daemon birth. Native TUI-to-daemon connectivity was
proved through the accepted socket's peer credentials; this establishes no
per-client current conversation mapping.

The native long-tool case collected 87 read/loaded snapshots with a maximum
gap of 0.431 seconds. Thirty-three reads overlapped an independently verified
running disposable tool before and after the RPC; every one reported the same
loaded thread and `active` with an empty `activeFlags` list. The surrounding
series reported idle before/after successful completion. The complete pinned
collector returned current source health, complete saved and loaded coverage,
the exact target and no errors in roughly 156 ms. Its accepted work subset now
includes working and settled; worker presence and current client binding remain
unsupported.

A subsequent on-request/workspace-write native client held an approval with
`activeFlags=["waitingOnApproval"]`. Explicit operator denial returned the same
thread to idle without creating the disposable target file. The collector now
accepts this approval wait separately; blocking user input and error/cancellation
distinctions remain pending.

Native `/new` produced a distinct unsaved loaded thread which the collector
included independently of history. Exact saved resume with `--all` reloaded the
original UUID through the same daemon. A further long-tool case kept the exact
tool process alive for 61 samples after its attachment TUI closed; 66 post-close
reads remained active before 17 idle reads and exact-session completion.

For recovery, the operator closed all owned clients, waited for work to settle,
and stopped only the verified disposable listener-owner birth. The candidate
CLI reported unavailable/zero rows without auto-starting anything. A new native
TUI then started a new daemon birth and resumed the same saved UUID. Passive
collection returned current/complete saved and loaded coverage with no errors.
Both exact private PID namespaces were later terminated, all private endpoints
and the borrowed auth copy were removed, and the sanitized result was retained.
Ordinary Codex auth matched its original fingerprint before and after cleanup.

The first failed resume's cause remains unknown because cwd and `--all` changed
between attempts. Current-conversation binding, worker presence, general input
wait and interrupted/error semantics remain unsupported. Installed ordinary
pilot results are a separate delivery gate, recorded below.
