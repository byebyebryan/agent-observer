# Working-set native byte-density screen

This saved source screen compares the current full and working-set native frames
at immutable source `610afaac658903ddd6c466c793f9856b45e9f03e` (runtime `bb7b8aa`).
It uses synthetic accepted snapshots, the same ordinary API4 rows on both routes,
and a fixed 72-hour window. Half the selected rows are active with old activity;
half are parked with activity one hour old. Other rows are parked with activity
ten days old. Inputs are strictly validated and complete working-set DTOs must
equal an independent filter of the original full DTOs. No provider, service,
Mesh, SDK, installed artifact or timing measurement is involved.

[Python 3.14](wire-314.json) and [Python 3.11](wire-311.json) each run twelve
cases with GC disabled. All scalar results, accepted-input digests and frame
sizes agree. The runner and eighteen loaded source modules are hash-bound;
the [checkpoint verifier](../review-checkpoint/verify_saved.py) independently
checks those blobs against Git, cross-version equality and byte arithmetic.

The condition uses original row bytes, not row count. The 500/120 case therefore
does not meet the plan's at-most-one-quarter prerequisite. The four refused
2,000-row cases do not become small successful views by returning a small
error/control. The earlier resource matrix's small 20-selected/2,000 case and
these larger selected unions have different capacity outcomes.

This is a native component comparison against the same current full source.
It does not establish the plan's complete accepted-a7/SDK/transport byte gate.
The 500/100 miss and the tracking refusals are reasons to resolve metadata
representation before claiming the general savings target. The separate
[support-density model](../support-density-model/README.md) quantifies repeated
receipt maps without changing or admitting a wire format.
