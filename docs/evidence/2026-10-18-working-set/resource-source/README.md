# Working-set source resource qualification

This is a reproducible, source-only resource screen for the working-set owner and the existing Service `Runtime` encoded-byte budget. Every case starts a fresh Python process, disables GC, feeds a synthetic snapshot through `ServiceState.accept`, and uses the real `Runtime._reserve_working_set`, `Runtime._queue`, and `Runtime._write` methods with local nonblocking socketpairs. It does not start a service, worker, provider, Mesh, SDK, or network client.

The source pin is `bb7b8aab91574fc3a325325ac8debf21b525712a`. Each case reports that revision plus SHA-256 hashes for the loaded Observer/test modules, the fixture JSON and the runner itself. The fixture is `tests/test_service_state.provider_snapshot("codex")`; the shape follows `performance-source/prepare_seed.py` by assigning the fixed synthetic UID and `/fixture/codex` namespace. The generated row identities, runtime status and activity timestamp create the matrix below; all other row fields stay from the ordinary fixture except in the separate long-title/cwd case.

Digest fields identify different material: `case.initialInputSha256` hashes the full canonical seeded snapshot before its session rows are reconstructed for acceptance; each `generations[].inputSnapshotSha256` hashes the full canonical snapshot passed to `ServiceState.accept`, including that generation's fresh collection ID, wall sample and complete rows. `fullDtoDigest`, `activeDtoDigest` and `workingSetDtoDigest` hash the respective emitted session DTO arrays; the last is null when no working-set projection is emitted. Only lengths, counts, digests and bounded metadata are written, never the raw snapshot bytes.

The default matrix contains eleven cases for each exact interpreter: the nine ordinary combinations of 100, 500 and 2,000 rows with the `small`, `quarter` and `burst` mixes, plus 2,000-row `small` and `quarter` cases with a 256-character ASCII title and 1,024-character ASCII cwd. The small-selection long case checks that large full-feed buffers can coexist with a complete, small working set; the quarter case also records whether bounded tracking can cover a much larger union. The frozen snapshot schema limits titles to 256 characters, so a 512-character title is invalid for this source contract. The long cases retain all other ordinary fixture fields. The runner validates every generated native snapshot against the frozen 8 MiB contract limit.

Active rows are running; recent-only rows are parked; recent rows have current activity at one hour before the synthetic wall sample, while nonrecent rows use ten days before it. Recent timestamps stay unchanged in all three accepted generations. Each generation has a new `collectionId`; wall and BOOTTIME samples advance together by 1 ms (`W=1,700,000,020,000 ms`, first `L=10,000 ms`, first accepted upper point `U=10,001 ms`). The synthetic time domain is `time:[123]`, matching the native SDK1 spelling. The snapshot’s wall sample and synthetic BOOTTIME bracket are constructed inputs, not a physical-clock bridge or runtime timing measurement.

For each generation, the runner checks full-feed row count and identities, active-feed identities, and—when working-set coverage is complete—exact membership plus DTO equality against the original full-feed rows. A bounded working-set frame or tracking refusal is recorded as `explicit_bounded_refusal` with its reason and output size; the runner does not call it a complete selection. Provider runtime health must remain current and all three runtime samples must be accepted.

There are fifteen local watch peers total: five per family across full, active and working-set routes, below Runtime’s sixteen-client cap. The 2/2/1 peer assignment rotates by family so every route has same-generation shared-body checks in two generations. One peer per family attempts a real nonblocking write while its receiver is not drained; older peer fragments and pinned cache bodies remain live while the next accepted state is staged. The report records peer drops, the cached body key behind every retained peer pin, unique buffer objects grouped by owner/cache/peer role, fragment references, current owner buffers and every observed encoded-byte counter point.

The reservation wrapper records Runtime’s actual current encoded bytes before the reservation, the existing worst-case stage request (`MAX_FRAME_BYTES + 2 * MAX_LEDGER_BYTES`), whether Runtime admitted it, and current bytes plus that request after its room/eviction work. It does not add a reservation, change the default 64 MiB limit, or count Python object graphs. Every pinned peer body part is listed as an alias and checked by object identity against the matching Runtime cache body; the conservative charge counts that body once through the cache. The report includes global unique buffer bytes, per-role unique attribution, role-overlap bytes (including shared body aliases and small shared fragments), and verifies the global unique total is no greater than the conservative charge. `encodedCounterHighWaterBytes`, `admittedReservationHighWaterBytes`, the per-point `Runtime.encoded_bytes()` value, and the independently assembled owner/cache/peer charge are separate from RSS. They qualify only the encoded-byte accounting already implemented by Runtime. Process current RSS and `ru_maxrss` are recorded separately and include interpreter imports, fixture/oracle objects, state, peers, and caches; they are not a heap or production RSS bound.

On cleanup, the runner drops all peers, closes both ends of each socketpair and the selector, clears Runtime body/latest references, removes the ServiceState reservation callback, and reports zero Runtime peers/cache bodies plus any owner buffers intentionally retained by the state. GC stays disabled. It does not claim terminal owner-buffer zero because the live ServiceState still owns its latest active and working-set frames.

`run_matrix.py` runs cases serially. Each per-case `.json` is scalar metadata, hashes, byte counts, counts and reasons; each `.log` records the exact child command and its scalar summary or exception. `summary.json` indexes those outputs and their hashes. No provider payload, prompt, session body or native response is written by this evidence.

The retained `reports/initial-before-review/` matrix is an earlier 20-case screen, superseded by the final source corrections to the clock spelling, peer-body alias inventory, long small-selection case and input digests. Its summary retains the earlier runner hashes, but those earlier script bytes were not saved; the final scripts do not reproduce that historical matrix exactly. No acceptance relies on that earlier screen. The `setup-diagnostics/` logs preserve the rejected 512-character-title fixture attempt: the frozen schema caps title length at 256, so those runs document invalid setup input rather than a source failure. The final eleven-case-per-interpreter matrix includes both long-title/cwd mixes and uses the supported 256-character title.

The final run produced 22/22 reports with zero runner or invariant failures, and each Python pair had identical input/output digests, selection status, encoded accounting and delivery observations after excluding interpreter-specific RSS fields. All 100-row cases completed. At 500 rows, small and quarter completed while burst returned the explicit `projection_tracking_capacity` refusal. At 2,000 rows, the ordinary and long-title/cwd small selections completed; ordinary quarter/burst and long-title/cwd quarter returned that same explicit tracking refusal. No stage reservation was refused. Across all cases, actual encoded-byte high-water was at most 20,185,255 bytes and requested current bytes plus the existing worst-case stage reservation at most 24,389,094 bytes, both under Runtime's unchanged 64 MiB limit. The largest input snapshot was 4,998,548 bytes, under the frozen 8 MiB limit. At every recorded point global unique buffer bytes stayed within Runtime's conservative charge; peak observed values were 20,185,231 unique bytes and 18,877,381 role-overlap bytes. Natural cache eviction occurred 14 times across the 22 reports (seven per interpreter); no Runtime peer drop occurred. Thus cache-eviction accounting was exercised, while peer-drop behavior was not. RSS was recorded only as process context, not as an acceptance bound.

These results are source-level encoded-resource evidence only. They do not establish CPU savings, Python heap/RSS bounds, live provider behavior, transport or SDK behavior, timer delivery, physical client behavior, or production capacity.

The 22 reports contain **14 complete-selection cases and eight explicit tracking refusals**. Zero runner/invariant failures does not convert those eight refusals into successful capacity qualification. The reservation/counter inventory covers encoded owner/cache/peer buffers; Python DTOs, containers, fixture/oracle frames and transient validation allocations are outside that inventory. Process RSS includes them but supplies no isolated bound.

Primary review inspected the source paths and accounting inventory, then ran [verify_saved.py](verify_saved.py) over the saved final reports without repeating the matrix. [primary-verification.json](primary-verification.json) verifies all 44 report/log digests, 31 loaded Git inputs against `bb7b8aab` and current source, eleven interpreter pairs, 770 counter points, reservation equations, cleanup and the selection/refusal distinction. Runtime object-identity checks occurred inside the original case runner; they cannot be reconstructed from scalar reports alone.

The original hash-bound runners are preserved exactly. [runner-lint.log](runner-lint.log) records 30 static findings, chiefly dynamic-import ordering, unused fixture scaffolding and loop/import rules; no lint-clean claim applies to those runners. The added primary verifier passes scoped Ruff. No production source, schema, identifier or selection changes accompany this evidence.
