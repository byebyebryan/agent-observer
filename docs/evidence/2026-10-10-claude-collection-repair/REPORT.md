# Change-aware Claude collection repair

The [execution plan](../../claude-collection-cost-plan.md) addresses the
[residual profile](../2026-10-10-residual-collector-cpu/REPORT.md). H0–H2 source
acceptance is complete. Immutable/native, sustained candidate and operational

## Source boundary and validation

The SDK worker shares a bounded tail/head read and per-record JSON decode between
kind and conversation activity. Their independent malformed/incomplete, UUID,
local-command, sidechain, clock and scan-budget rules remain intact. Projected
envelope fields live only within the bounded scan; raw lines/message/tool bodies
never enter the inter-worker memo. Ordinary catalogue/SDK listing remains fresh.

The service wrapper retains a private volatile normalized memo between owned
workers. The passive adapter authenticates current home/projects/project directory
incarnations and file device/inode/size/mtime/ctime/owner/mode for every hit, then
checks the guard again. Changes, replacements, unsafe paths and failed guards
force native parsing. A successful positive saved UUID check can also be reused;
current native registrations, all matching exact process/image checks, conflict
guards and work phase remain independent and fresh. No cached presence or phase
exists. Filesystem timestamps detect changes; activity keeps its native timestamp.

Entries are limited to 2,048 and encoded metadata to 1 MiB. Input crosses a sealed
read-only memfd, explicitly inherited by the owned helper; it cannot block on a
socket buffer. SDK and outer worker replies use strict private metadata fields;
service admission still validates the full ordinary snapshot before accepting
receipts. Invalid transport, timeout, stale scheduler generation, rejected sample
or changed provider context discards reuse. Cache loss/eviction reparses native
files. Unknown/fault projections are not cached. No persistent transcript store,
append ledger, provider-policy, networking, attachment or frontend work is added.

Source validation passes 443 tests with no skips in the existing optional-Mesh
interpreter. Fourteen new tests include 250 seeded stable-input comparisons with
the frozen a14 parser, independent activity/kind budget results, decode avoidance,
append/truncate/atomic replacement/deletion, symlink/permissions, home/project
replacement, UUID conflict, malformed/incomplete records, stale parse/hit races,
eviction and encoded bounds. Actual owned workers prove sealed transfer,
normalized reply admission and rejection/context/timeout/generation cleanup.
Existing SDK isolation/audit and helper deadline/group cleanup tests also pass.

## Controlled cost and parity

The [read-only study operator](../../../scripts/study-claude-collection) uses the
exact selected Snap Python 3.12.8 and native files, retaining counters only.
[Parser results](parser-source.json) compare 37 stable UUID candidates with zero
activity/kind differences. Source files did not change within this study.

| Parser path | CPU seconds, uninstrumented | JSON records, separate counted run | Decoder input |
| --- | --- | --- | --- |
| Frozen a14 separate activity/kind | 0.3084 | 19,097 | 36.20 MB |
| Shared cold parser | 0.1795 | 7,547 | 18.31 MB |
| Warm normalized memo | 0.00187 | 29 | 41.6 KB |

The memo holds 35 successful projections in 13.3 KB encoded metadata. Remaining
unknown/fault projections retain fresh reads. A three-file synthetic proof changes
one native activity record: exactly one record is decoded, the two other
projections stay equal and the changed native activity advances 1,000 ms.
No ordinary history is mutated; no hint is required for detecting the change.

The controlled full-adapter studies compare [installed a14](components-a14.json)
and [source a15](components-source.json), with the same Python 3.12.8 and normal
image memo, unchanged ordinary provider files and fresh SDK children. Warm
runtime-only cost falls from 0.0578–0.0583 to 0.0140–0.0150 CPU seconds. Cold
image authentication remains about 0.75 seconds. Shared-cold history costs about
0.319 CPU seconds; warm history costs 0.132–0.138 versus a14's 0.457–0.497 seconds
(parent plus reaped SDK child). Both return 37 rows/current source health. Memo
metadata is about 14.5 KB including positive UUID facts.

These are bounded component studies with amortized parent imports and ordinary
files potentially changing between runs. They establish meaningful source cost
reduction, not sustained host savings or native runtime completeness. Installed
public CLI/native comparison and ten-minute normal workload measurements remain
independent acceptance requirements before managed collector selection.
