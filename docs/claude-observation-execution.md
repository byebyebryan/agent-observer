Historical a8 execution pass. The completed
[interactive successor](claude-observation-wrap-up.md) accepts and selects a9.
The source and lifecycle rules below retain their original evidence bounds;
they do not define current support for background jobs or saved-only absence.

This pass adds Claude discovery and monitoring to the established passive
observation boundary. Codex remains independently accepted. API 2 rows retain
exact session UUIDs, running/parked/unknown disposition, working/blocked/waiting
phase, conversation activity and explicit coverage. No terminal, tmux, window,
attachment, action, networking or alert policy belongs to this pass.

## Native source gate

Reinspect Claude on Snap. Prove candidate reads in disposable user/mount/PID
namespaces before using any CLI that could initialize preferences, adopt orphan
workers or start a supervisor. An advertised JSON list is not evidence of
passivity. Reject a mutating read route rather than using it on ordinary stores.
Provider-owned session registration and retained-job metadata may supply a
bounded required contract when authenticated by exact UUID, native PID domain,
process birth and source ownership. These checks authenticate native records;
they do not discover or match terminal contexts.

Running requires a positively authenticated native session registration or a
separately proved logical background-runtime predicate. Worker absence, history
existence and inventory omission alone do not prove parked. Initially retain
unknown for saved sessions without a positive lifecycle predicate. Terminal
retained jobs require native terminal state, no pending work, complete stable
source inventories and no bound worker before parked can be accepted. No new
background action support is implied.

Busy and shell status require held native proof for working. Interactive idle
requires native readiness proof for waiting. Permission and question waits need
separate held proofs; unsupported dialogs preserve running and unknown phase.
Activity uses conversation event clocks, independently of registry heartbeat,
title updates, sampling and process lifetime. Child classification remains native
and default presentation hides only confirmed children.

## Checkpoints

1. Native passivity/topology and required-field review. Record finite outcomes
   without retaining raw provider payloads or conversation contents.
2. Enable one passive adapter for direct reads and service helpers. Project
   provider metadata to the existing public model; keep classifiers out of the
   service and read clients. Reuse filesystem wakeups only as refresh hints.
3. Source checks cover malformed/torn/conflicting identity, partial inventories,
   native status and clock changes, stopped workers, saved metadata and retention.
   Codex and import/dependency boundary checks must continue to pass.
4. Freeze an immutable candidate. Independently compare ordinary native Claude
   records on Snap to its installed direct/cached/pushed reads. Use isolated
   working, waiting, approval/question, exit, retained-job and source-fault cases
   for lifecycle proof. Validate age, identity and child filtering separately.
5. Only after artifact/native acceptance, select the scoped read/service artifact
   through its independent operational gate. Preserve the separately selected
   writer, provider settings, hooks, ordinary sessions and consumer repositories.

Run `./scripts/check` before each commit. Report unsupported classifications as
limits, not inferred state. No provider-version/hash allowlist, history migration
or ordinary provider restart is required. At the start of that pass, installed a6 rejected Claude;
earlier a16 evidence is historical and does not accept this new adapter.
