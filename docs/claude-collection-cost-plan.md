# Claude collection cost execution

The user authorized a regular goal loop following the
[residual CPU profile](evidence/2026-10-10-residual-collector-cpu/REPORT.md) and
discussion of change detection. This is a passive producer repair. The target is
less repeated transcript decoding at the accepted cadence, with unchanged
API 2, snapshot/watch 4 and Service 2 behavior. Collector selection follows
independent artifact/native/cost acceptance; reader, writer, Mesh and provider
policy keep their separate selections.

## Implementation boundary

The Claude adapter owns native reads and validation of memo reuse. The service
retains a bounded, volatile memo between its short-lived collection workers and
transfers it privately. Core reconciliation/public views receive normal complete
snapshots. Native hints keep their existing coarse scheduling role; a fresh
bounded catalogue check detects changes even when hints are missed.

The memo contains only exact file/directory incarnation metadata, positive saved
UUID checks, normalized session kind and native conversation activity provenance.
It holds no prompts, responses, tool contents, provider registration/process
facts or work phase. Current file/path/ownership checks must authenticate every
reuse. Filesystem clocks detect changes and never become conversation age.

Runtime registration, exact process/image authentication, conflict guards and
phase reads stay fresh on every collection. No history memo grants a parked
classification without the adapter's independent current native predicate.
Cold start, memo loss or eviction reads native data again. Source faults,
replacement, deletion, ambiguous candidates and changed namespace invalidate
reuse; unknown/failure must remain explicit. Admission/public validation and
observation leases/retention remain intact.

## Bounded mechanism

- Share one bounded head/tail read and JSON decode between activity and kind,
  preserving their separate results and existing scan-budget charging. Retain
  identity, duplicate-key, malformed/incomplete-record and local-command/sidechain
  rules. Stable inputs must match frozen original helpers.
- Retain normalized successful projections by exact configured namespace,
  parent-directory identities, relative file identity and full change stamp.
  Each hit freshly opens/checks the current source. No event alone authorizes reuse.
  New/changed files are reparsed; cheap catalogue/SDK metadata listing remains.
- Bound entry count and encoded bytes. Transfer read-only input through an owned
  sealed descriptor, avoiding socket-buffer deadlock before a worker reads its
  request. Return an explicitly validated private metadata envelope with the
  complete worker snapshot. Do not extend the public snapshot/frame contracts.
  Bound helper output and retain existing deadlines/group cleanup.
- Reuse no memo across a rejected/failed sample or changed provider context.
  Clear it on service failure/invalid transport and after shutdown. Direct reads
  remain self-contained; they benefit from shared parsing but need no durable cache.

## Acceptance sequence

1. H0: document source/worker/cache ownership, freeze original pure parser helpers
   in test-only code and establish selected a14 provenance. Review transfer bounds
   and partial/fault behavior before source changes.
2. H1: implement shared parsing and per-file normalized memo. Prove stable-input
   old/new parity, unchanged-file decode avoidance, changed-file refresh, current
   native registration independence and bounded memory/transport. Cover append,
   truncation, atomic replacement, rename/deletion, permissions/ownership,
   directory replacement, duplicate UUIDs, malformed/incomplete records, budget
   boundaries, omitted SDK candidates, cache eviction/cold start and lost hints.
3. H2: run source checks and controlled exact-interpreter cost studies. Admit a
   source checkpoint only with meaningful decode/CPU reduction and preserved
   discovery/monitoring/age/retention contracts. Commit the accepted source.
4. H3: freeze an immutable successor collector, install independently on Snap
   (Claude/Codex) and Starship (Codex), and compare installed direct/cached/pushed
   reads with independent native evidence. Use isolated fixtures for fault/change
   proofs; preserve ordinary sessions/settings. No terminal/client inventory.
5. H4: measure at least ten unprofiled minutes of ordinary candidate workload on
   both hosts, separating publisher and helpers, reporting metadata/memory bounds
   and comparing observation freshness. Accept no invented idle floor. Commit
   artifact/native/cost evidence before selection.
6. H5: scoped collector rollback/reselection on both hosts, with normal-unit
   native/delivery and sustained-cost verification. Preserve reader/writer/Mesh,
   provider workflows and unrelated managed drift. Update handoff/status and
   commit accepted operational evidence. Push remains a separate user request.

No slower cadence, new hook requirement, append-only transcript ledger, persistent
SDK runtime, alert protocol or downstream implementation is included. Appended-byte
tailing and broader publisher optimization remain later measured decisions.

## Completion checkpoint

H0–H5 are accepted in the [execution report](evidence/2026-10-10-claude-collection-repair/REPORT.md).
Normal collectors select immutable a15 on Snap and Starship after independent
native/cost proofs, a14 rollback and a15 reselection. Source passes 443 tests;
the matched Snap window reduces total CPU from 3.493% to 2.353% of one core.
Final ten-minute normal-unit windows measure 2.003% on Snap and 2.340% on Starship.
API 2/wire 4/Service 2, cadence/hints and reader/writer/Mesh/provider policy remain
unchanged. Changed-file tailing beyond the existing bounded parser is deferred.
