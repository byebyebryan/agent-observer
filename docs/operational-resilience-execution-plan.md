## Baseline and bounded findings

Observer `0.2.0a7` is selected on Snap and Starship. Plus `0.14.0a1` and its
`0.2.0a3` reader dependency are frozen. Ordinary Claude on Snap upgraded from
`2.1.287` to `2.1.289`; both executable incarnations still have resident
processes. The current adapter's exact installed-artifact gate rejects the new
binary, while the SDK still returns 25 saved sessions with conversation clocks.
Public saved coverage incorrectly depends on the failed live aggregate and
marks those fresh histories unavailable. The CLI's version label is stale,
human activity is an epoch number, and text diagnostics omit finite errors.

Two Claude UUIDs have a full transcript and small worktree metadata-only file.
The current census marks both ambiguous and omits them. This requires a bounded
native-layout classification proof, not deletion or arbitrary path preference.
Conflicting conversation histories must remain explicit and action-ineligible.

Codex public Resume preparation succeeds for the current conversation and saved
ESP32 conversation. Its live inventory is scoped to loaded daemon threads;
client process counts and resume argv do not prove current conversation binding.
Audit manually resumed topology without converting ordinary clients or inferring
identity from process/title/cwd. The Plus handoff association defect and silent
terminal launch remain a consumer checkpoint.

## Ordered checkpoints and exits

1. **S0 capture.** Reinspect both hosts' selected bytes, providers, runtime scope
   and ordinary configuration/authentication hashes. Record bounded counts and
   reasons only. Preserve existing sessions and unrelated drift.
2. **S1 independent read health and CLI.** Derive saved coverage/aggregate health
   from the saved observation rather than live success. Fresh history remains
   fresh with unknown live state. Correct package/CLI version consistency,
   readable age and finite explanatory doctor diagnostics. Read/watch/fixture
   tests cover partial failure and unchanged activity; JSON shape stays v2.
3. **S2 native layouts and version support.** Centralize exact verified artifact
   support shared by observation and the separate writer. Prove Claude 2.1.289
   work/approval/readiness, job/worker identity and New/attach/saved Resume in
   isolation. Inspect surviving process images independently of the installed
   executable inode. Unknown images stay unsupported. Recognize bounded
   metadata-only companion files only with an exact single conversation source;
   malformed/conflicting/growing/oversized cases remain ambiguous.
4. **S3 route-specific write proof.** Audit evidence for New, live attach and
   saved Resume. Reuse the passive prepare boundary and preserve executable,
   directory, identity, selector and execution-time guards. Native PTYs prove
   entry, partial feeds, copied identities and visible failures. Missing-daemon
   Codex Resume receives a supported route only if independently proved; no
   ordinary auto-start or legacy history reader is added to passive observation.
5. **S4 fresh artifact gate.** Freeze a reviewed source, build/install a new
   candidate outside the checkout, verify CLI version against wheel metadata,
   exact bytes/schemas, source tests and native enabled-route cases. No Plus
   implementation is used to make this gate pass. Record scoped runtime limits.
6. **S5 scoped delivery and cleanup.** Only after S4, review compatible producer
   selection on both hosts, preserving the frozen Plus reader and unrelated
   managed paths. Verify selected passive/headless reads independently. Stop
   exact owned namespaces, remove borrowed authentication/private history,
   verify ordinary file hashes, document any concurrent preference drift and
   commit the handoff. No public push is inferred.

## Boundaries

Snapshot/watch v2 and write v1 remain prerelease contracts. Existing shape and
documented semantics must be sufficient before a compatible selection; new wire
fields require a separately versioned consumer migration. Action readiness
belongs to the first-party write client, not passive core authority. General
questions, parked inference, current-viewer binding, physical sleep/wake, hooks,
networking and graphical Plus acceptance retain their independent gates.

Native experiments use repo-owned user/mount/PID isolation, private configuration,
endpoints and authentication copies before any provider launch. Native output
and conversation bodies are discarded. Evidence contains bounded metadata,
counts, hashes, finite reasons and acceptance booleans only. No fixture enters
ordinary history; no current session is resumed concurrently or restarted.
