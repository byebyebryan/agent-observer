# Native observation validation

Validate the installed public CLI against independent native evidence when
provider/runtime behavior changes. Current scope is Codex-only API 4,
snapshot/watch 6 and Service 4. Source tests and another Observer result are
not independent native proof. Documentation-only changes need no provider action.

## Ordinary passive comparisons

1. Record the installed artifact, host/home namespace, provider metadata and
   daemon topology. Run the public entrypoint outside the source checkout.
   Versions/hashes are provenance and incarnation guards, not support allowlists.
2. Capture bounded direct snapshot/list diagnostics and the explicit existing
   Service 4 endpoint. Record sample/emission time, component leases, saved/runtime
   coverage and read health. Cached clients must start no service or collection.
3. Independently query the authenticated owning Codex daemon using passive
   metadata-only RPCs: scoped `thread/list`, `thread/loaded/list`, `thread/read`
   and `thread/turns/list` excluding items. Establish UID, namespace and daemon
   incarnation; process identity authenticates the endpoint, not session phase.
   The [evaluation harness](../../scripts/evaluate-observation) imports no
   Observer collector and records bracketing native comparisons.
4. Compare exact thread identity separately from tree-root metadata, then runtime,
   phase, kind, native conversation clocks and declared coverage. Titles, cwd,
   terminal presence and process counts do not prove identity or running state.
5. Bracket transitions with timestamps and a second native sample. Distinguish
   demonstrated mismatches, observations made at different instants, missing
   evidence and unsupported topology. Unresolved classifications stay unresolved.

Daemon `idle` is running/waiting; supported active state is running with its
proved phase, while native error/unsupported wait evidence can leave phase
unknown. Current `notLoaded` plus positively readable saved identity is parked.
Loaded-list absence, worker exit or a closed TUI alone do not establish parked.

Fresh source health means a successful observation within its declared scope.
It does not establish exhaustive membership or a known phase for every worker.

## Cached, fleet and working-set proof

Check exact source/publisher/incarnation/clock bindings and independent leases.
Compare full/resync baselines against native samples. A heartbeat proves only
transport liveness. Gaps revoke positives until a valid resync; quiet ticks must
expire facts without new delivery. Current-view agreement does not prove lossless
transitions, durable replay or completion-alert delivery.

For working-set, compare active membership independently of recent-window
membership and scope coverage. Partial/empty member arrays cannot prove absence.
Host/home and remote-route acceptance remain endpoint-specific.

## Controlled cases and delivery

Use isolated operator-owned homes, workspaces and endpoints for controlled
working, approval/question, completed-turn, child, parked and recovery cases.
Establish isolation and cleanup ownership before native entry. Preserve ordinary
sessions, hooks, settings, services and processes. Physical sleep/wake and
post-TUI-closure lifetime remain separate qualification scopes.

Keep only bounded metadata, timestamps, reasons and comparison outcomes in
receipts: no conversation/tool bodies, credentials or terminal captures.
Qualify source, immutable package, installed role, native producer, consumer and
physical behavior independently. New production bytes need their own installed
and affected-native gates; no writer/Claude test is part of current scope.
