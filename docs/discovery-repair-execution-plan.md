## Reopened acceptance

The selected `0.2.0a3` producer returns no conversation activity timestamps.
That explicit limitation preserves evidence semantics, but prevents the required
age and ordering workflow. Treat recency as discovery acceptance, not an optional
monitoring expansion. Creation, file modification, sampled state and conversation
activity clocks remain distinct.

Ordinary Snap Claude metadata exposes a live background job without `state.json`
and a native job state `blocked` that the accepted parser does not recognize.
These errors stale the whole provider feed and prevent unrelated saved Resume.
Closing TUIs also leaves verified native background workers running; two actual
session identities can share a name. Never resolve identity from that name or
delete ordinary jobs to make collection succeed.

The current Codex session is now daemon-observable, and passive preparation for
loaded and saved Codex identities succeeds. The reported silent picker Resume
failure has not been localized. A prepare success is not terminal-entry proof.

## Sequence and completion criteria

1. **R0 baseline and source decisions.** Verify both installed providers on Snap,
   Codex on Starship, selected package paths and ordinary configuration hashes.
   Capture bounded counts/errors only. Investigate native chronology semantics,
   including unchanged age after reads, rename, attach/resume and maintenance.
   Establish owned isolation before any action that can start a provider.
2. **R1 chronology.** Select a version-gated metadata activity source per provider.
   Preserve null/unknown when evidence is missing, ambiguous, malformed or outside
   bounds. Order by accepted activity before display caps, or expose recoverable
   coverage that cannot silently omit an old recently active conversation. The
   public `activity` field supplies provenance; collection never substitutes
   its own clock. Reuse schema v2 only if its existing shape/semantics suffice.
3. **R2 Claude resilience.** Recognize native `blocked` only with independently
   accepted state/reason semantics. Distinguish incomplete jobs from unavailable
   whole sources. Keep verified worker identity and independent saved history
   usable; unknown work remains unknown. A bad sibling cannot invalidate a
   healthy saved or live action target. Validate exact target evidence rather
   than treating aggregate partial health as blanket action authority.
4. **R3 write entry.** Exercise installed public prepare/execute/enter under a
   real PTY for Codex New, saved Resume, repeated live entry and runtime recovery
   on both hosts. Include native entry rejection/exit visibility as an explicit
   result boundary. Native mutations are confined to disposable owned stores.
   If only a consumer presentation defect remains, record its reproducible
   boundary and defer its implementation to the separate consumer checkpoint.
5. **R4 independent artifact acceptance.** Build a distinct candidate package;
   verify installed bytes, public schemas and source/conformance tests. Prove
   chronology invariance and advancement, Claude partial-feed recovery and
   target-scoped Resume through first-party CLIs independently of frontend code.
   Preserve healthy partial reads and unknown states in watch recovery.
6. **R5 delivery handoff and cleanup.** Stop only exact owned native namespaces,
   remove borrowed authentication/private histories and verify ordinary provider
   configuration hashes. Record commits, exact candidate versus selected package
   status, provider/version/topology coverage and any unresolved consumer issue.

## Delivery boundaries

Source acceptance does not silently replace either selected package. Candidate
installation is reversible and belongs to the independent Observer artifact gate.
A scoped producer selector update may follow only after that gate and a checked
compatible public schema; it must preserve the selected consumer artifact and
unrelated managed drift. New schema shapes or incompatible semantics require a
separate consumer migration instead. Public publication/push is not inferred.

No ordinary hooks, provider settings, sessions, workers or Tmux servers are
modified. Repository evidence contains finite reasons, metadata counts and
acceptance booleans only; native output is filtered in memory and discarded.
