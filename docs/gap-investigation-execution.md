Each gap receives one of: independently fixed and accepted, capability proved
within stated bounds, contract/source limitation with concrete next proof, or
external/operator/client gate. A failed experiment is retained as bounded
metadata rather than promoted to runtime support.

## Execution boundaries

- Passive ordinary comparisons never start, resume, stop, rename or delete
  provider sessions. Native actions and optional hooks use verified disposable
  user/mount/PID namespaces with ordinary stores masked before startup.
- The selected a7 Observer units and provider policy remain the baseline while
  source/candidate work is accepted independently. A new selection requires its
  own exact artifact, six-target drift review and operational gate.
- Agent Plus implementation, existing notification wiring, new networking,
  firmware/device actions, physical suspend/reboot and public release are
  separate. Their gaps are investigated and handed off without a combined
  producer/frontend edit cycle.
- Evidence retains bounded identities, metadata, clocks, counters, predicates
  and finite reasons only. Credentials, callbacks, prompts, model/tool output
  and terminal captures remain outside repository evidence and are removed.
- Run `./scripts/check` before each commit. Match the installed public CLI to
  independent native evidence under the
  [validation workflow](observation-validation-workflow.md). Tests of another
  Observer projection do not establish native completeness.

The prior [operational baseline](observer-operations-execution.md) and
[service handoff](shared-observation-service-handoff.md) remain accepted within
their original scope. Investigation findings do not silently redefine API v1
or the separately prerelease service protocol.
