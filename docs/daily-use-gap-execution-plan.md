## Decisions to preserve

- Saved discovery, loaded/registered runtime, work phase, terminal attachment
  and logical lifecycle are distinct. Saved-only absence does not establish
  parked or stopped. A complete native runtime scope is narrower than all
  possible provider processes.
- Partial history must preserve previously observed saved evidence, not turn a
  former runtime observation into indefinite saved membership. Removal from a
  sampled view is not provider deletion. Do not use UUID titles, cwd, PID or age
  as a child or deletion classifier.
- New finite diagnostics are compatible with API 1. New fields, enum values,
  changed meaning or action capabilities require their own contract/native gate.
- A timestamp difference is not event-to-view latency. Native wakeups retain
  periodic reconciliation and current receipts do not promise latest messages.
- Configure roots explicitly; project grouping is not cross-host identity.
  Missing historical directories require a clear rejection or a separately
  designed relocation workflow, never a guessed replacement path.
- Provider support follows required contracts. Native versions/hashes remain
  diagnostic and context guards, not release allowlists. Existing foreground
  workers, hooks, provider settings and active work stay intact.
- Physical suspend, native dialog cases that cannot be held safely, notification
  routing and device/mesh delivery retain separate operator/consumer gates.
